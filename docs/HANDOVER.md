## プロジェクト名について

2026-08-03 に **ClaudeDeck → PaneDeck** へ改名した。特定ベンダーの名前を冠すると
Claude Code 専用に見えるが、実際には起動コマンドを差し替えれば Codex / Gemini CLI など
CLI で動くエージェントは何でも並べられるため。

- 製品名としての `ClaudeDeck` / `claudedeck` は全て置換済み
- **エージェントとしての Claude Code への言及は残してある** — 起動コマンドの既定値
  `claude` と、`lib/status-detector.js` の入力待ちパターン（Claude Code の UI 由来）は
  そのまま。ここは事実なので消さないこと
- 新機能を足すときは特定エージェント前提にしない。エージェント固有の値は設定として
  外に出す

## 設計の要点（なぜそうしたか）

### ロジックを lib/ に隔離した

`lib/` の3モジュールは **Electron にも node-pty にも依存していない**。
`SessionManager` は pty 生成関数を、状態判定は現在時刻を、それぞれ**依存性注入**で受け取る。

この形にしたおかげで:

- 単体テスト 81 件が Electron 起動なしで 0.7 秒で回る
- 「出力が止まって 400ms 経つと待機になる」といった**時間依存の遷移を実時間に頼らず**検証できる
- E2E でも同じ差し替え口（`global.__sessionManager`）を使い、実プロセスなしで決定的にテストできる

新機能を足すときも、まず `lib/` に純粋なロジックとして書いてから `main.js` の IPC で
繋ぐ順序を守ると、テストが書きやすい状態を維持できる。

### レンダラはポーリングで追従する

レンダラは 300ms ごとに `session:list` を取り、画面上のペインと突き合わせて増減させる
（`renderer.js` の `sync()`）。ペイン生成経路が 1 箇所に集約されるので、UI からの追加でも
ワークスペース復元でも同じ流れになる。E2E から直接 `window.deck.createSession()` を
呼んでもペインが出るのはこのため。

### 実プロセスのテストは 1 ファイルだけ

`tests/e2e/real-pty.spec.js` だけフェイクを使わず、短命なコマンド（`echo`）を実際に
起動して pty 連携そのものを確認する。他は全部フェイク pty。

## ハマりどころ（再発しやすい）

### 1. contextBridge のグローバルと同名の const を宣言すると全部落ちる

`preload.js` が `exposeInMainWorld("deck", ...)` しているので、レンダラ側で
`const deck = window.deck` と書くと **"Identifier 'deck' has already been declared"** で
`renderer.js` 全体が実行前に落ちる。イベントリスナも一切登録されず、画面は静止するが
エラーは DevTools を開かないと見えないので気づきにくい。

現在は `const api = window.deck` にしてある。**この別名は変えないこと。**

### 2. テストのリセット直後はペインがまだ残っている

レンダラはポーリングで追従するため、`closeAll()` した直後もペインは最大 300ms 残る。
そのまま `waitForPaneCount(page, 1)` すると**前のテストの残骸ペインで即座に成立**し、
消える寸前のペインを操作してしまう。

`resetSessions(electronApp, page)` は page を渡すとペインが 0 になるまで待つ。
**新しいテストを書くときは必ず page を渡すこと。**

### 3. ネイティブダイアログはテストを止める

`window.alert` / `confirm` はモーダルでレンダラをブロックし、E2E が復帰不能になる。
通知はツールバーの `#message`（`showMessage()`）に出す方針にしてある。

### 4. node-pty は Electron 向けに再ビルドが要る

`npm install` 直後は Node 用にビルドされているため、`npm run rebuild` を忘れると
起動時にネイティブモジュールの読み込みで失敗する。

## 次にやると良いこと

優先度が高いと思う順:

1. **セッションごとの起動コマンド** — 今はツールバーの1つを全セッションで共有している。
   リポジトリによって `claude` / `claude --continue` を使い分けたい場面が出るはず
2. **最後の構成の自動復元** — 起動時に userData の既定ワークスペースを読む。
   今は毎回ファイル選択ダイアログが要る
3. **入力待ちペインだけに送る** — 状態でフィルタして broadcast する。
   現状の一斉入力は状態を見ずに全部へ書き込むので、実行中のペインにも届いてしまう
4. **ログの自動ファイル出力** — 今はメモリ上のリングバッファ（末尾50万文字）で、
   アプリを閉じると失われる
5. **ペインの並べ替え・レイアウト保存**
6. **アイコンとパッケージング**（electron-builder など）

## 注意している制約

- `lib/status-detector.js` の入力待ち判定は **Claude Code の UI 依存のヒューリスティック**。
  入力ボックスの罫線や選択肢マーカーが変わったらパターン追加が必要になる。
  変更時は必ず `tests/unit/status-detector.spec.js` にケースを足してから直すこと
- ログ上限は `SessionManager` の `maxLogBytes`（既定 50 万文字）。超えると古い方から捨てる
