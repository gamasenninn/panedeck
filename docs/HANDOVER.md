## 設計の要点（なぜそうしたか）

### ロジックを lib/ に隔離した

`lib/` は **Electron にも node-pty にも依存していない**。pty 生成関数・現在時刻・
設定やログの保存先パスを、すべて**依存性注入**で受け取る。

おかげで単体テスト 275 件が Electron 起動なしで 2 秒弱で回り、「出力が止まって
400ms 経つと待機になる」といった時間依存の遷移も実時間に頼らず検証できる。

新機能はまず `lib/` に純粋なロジックとして書き、`main.ts` の IPC で繋ぐ順序を守ること。

### 状態も並び順もメインプロセスが持つ

レンダラは 300ms ごとに `session:list` を取って画面と突き合わせる（`sync()`）。
**この構造では、レンダラ側に真実を持たせると必ず巻き戻る。**

- 並び順は `SessionManager.reorder()` が持つ。レンダラが持つと、ポーリングのたびに
  突き合わせが要り、書き損なうと並びが戻る
- 一斉入力の状態フィルタもメイン側で判定する。レンダラの状態は最大 300ms 古い

### E2E は実ユーザーの環境を触らない

`launchApp()` は設定パスを渡さなければ**使い捨ての一時ディレクトリ**を使う。
渡さないと実 userData を読み書きしてしまい、テストがユーザーの設定に従って動き、
ユーザーのフォルダにテスト用のログを書き散らす（実際に起きた）。

### 実プロセスを使うテスト

`real-pty.spec.ts` と `auto-restore.spec.ts` はフェイクを使わない。前者は pty 連携
そのもの、後者は**起動時の復元がフェイクを差し込む前に走る**ため。
`tests/packaged/` は生成物を起動して、パッケージ版だけで壊れる経路を見る。

## ハマりどころ（再発しやすい）

### 制御文字は必ず `\x1b` のように書く

`status-detector.ts` の `ANSI_PATTERN` には**生の ESC バイトが直接埋まっていた**。
ソース上で不可視なので、TS 化で書き写したときに落ちた。ESC が無いとパターンが
ただの `[` に一致し、プロンプトの `[Y/n]` を ANSI と誤認して削っていた。

### ANSI の除去は取りこぼすと判定が丸ごと死ぬ

この一連で 4 つ直した。**どれも特定のエージェントの話ではなく、全体の入力待ち
判定を壊していた。**

| 欠陥 | 影響 |
|---|---|
| OSC に終端が無い | 最初の OSC 以降を末尾まで削除（実ログで 4405 文字 → 46 文字） |
| 行数の窓が空行を数える | 全画面 TUI は画面下を空行で埋めるので中身が窓の外へ出る |
| 宙に浮いた ST が残る | 末尾 2000 文字の境界が OSC の途中に落ちたとき |
| CSI の中間バイト非対応 | `ESC [ 0 SP q` が本文に残る |

**シェルはプロンプトのたびにタイトル設定の OSC を出す**（PowerShell も）。
1 つ目は事実上すべてのエージェントで判定を殺していた。

### 状態を見ない pty 操作は落ちる

`resize()` は終了済みセッションを弾く必要がある。node-pty は終了した pty の
リサイズで例外を投げ、レンダラは文字サイズ・列数・ウィンドウの変化のたびに
全ペインへ resize を投げるので、**終了したペインが 1 つ残っているだけで
メインプロセスの未処理例外**になる。`write()` と同じ扱いにそろえてある。

### xterm の癖（3 つとも実際に時間を溶かした）

- **空行でも `hasSelection()` は true、`getSelection()` は空文字列。**
  端末の中央をクリックすると空行に当たる
- **`.xterm-rows` はポインタイベントを受けない。**行の div はクリックできず、
  Playwright は操作可能になるのを待ち続けてタイムアウトする。選択は
  `.xterm-screen` に座標指定で行う
- **`attachCustomKeyEventHandler` が `false` を返しても、ブラウザ既定の動作は残る。**
  隠しテキストエリアに文字が入り二重に送られる。`preventDefault()` が要る

### 隠れているペインは測らない

`fit()` はレイアウトを持たないペインを飛ばす。測ると 0 桁になり、その値で pty を
リサイズしてしまう。1 ペイン拡大でも並べ替えでも通る経路。

### レンダラは ES モジュール（相対 import に `.js` が要る）

バンドラを挟んでいないので、`./renderer/keys.js` のように**拡張子まで書く**
（`.ts` ではない）。npm の bare import は解決できないため、xterm は script タグで
読み込んだグローバルを使う。

かつて「レンダラで `const deck` と宣言するとスクリプト全体が落ちる」という地雷が
あったが、**モジュール化で解消した**（トップレベルの名前がモジュールに閉じるため）。
`const api = window.deck` はそのままだが、もう別名にする必然性は無い。

### テストのリセット直後はペインがまだ残っている

`resetSessions(electronApp, page)` は page を渡すとペインが 0 になるまで待つ。
渡さないと**前のテストの残骸ペインで即座に成立**する。**必ず page を渡すこと。**

### ネイティブダイアログはテストを止める

`window.alert` / `confirm` はレンダラをブロックし E2E が復帰不能になる。
通知は `showMessage()` へ。

### PowerShell から git commit するとき

`-m` にヒアストリングを渡すと、中の引用符や `--` で引数が壊れる（2 回踏んだ）。
**メッセージはファイルに書いて `git commit -F` を使うこと。**

## 調査の道具

### `scripts/inspect-log.mjs`

保存したセッションログを、**判定が実際に見る形**（末尾 2000 文字 → ANSI 除去 →
空行を除いた末尾 10 行）で表示し、プロファイルごとの判定結果も出す。

```bash
npm run build
node scripts/inspect-log.mjs logs/codex.log
```

**判定ロジックは再実装せず、ビルド済みの本体を呼んでいる。**一度写して持った結果、
本体を直してもスクリプトが古いままで「直したのに直らない」と誤認した。

エージェントを足すときの手順:

1. そのエージェントを PaneDeck で走らせ、入力待ちで止める
2. ペインの **ログ** ボタンで保存（生の出力が要るので `logStripAnsi` は false 推奨）
3. このスクリプトに掛けて、判定が見る文字列を確認してからパターンを起こす

**実機で確かめたものだけを足すこと。**当て推量の正規表現は「実行中を入力待ちと
見なす」方向に倒れ、誤検知は取りこぼしより悪い。

### `npm run test:packaged`

`npm run pack` の生成物を起動し、asar からの読み込み・ESM の解決・node-pty の
読み込み・設定の読み書きを確認する。パッケージ版だけで壊れる経路を見るためのもの。

## パッケージング

- **`npmRebuild: false`** — node-pty のプリビルドをそのまま使う。ソースからの
  再ビルドを走らせると winpty の `GetCommitHash.bat` が無くて node-gyp が失敗する
- **node-pty は `asarUnpack`** — conpty の補助実行ファイルを同梱しており、
  asar の中の実行ファイルは起動できない
- アイコンは `build/icon.svg` が正。`npm run icon` で PNG を作り、`.ico` / `.icns` は
  electron-builder が生成する

## 次にやると良いこと

差し迫ったものは無い。候補:

- **`strict` / `noImplicitAny` を上げる** — `strictNullChecks` は有効済み。
  残りを段階的に
- **設定 UI** — `logDir` / `logStripAnsi` / `logRetentionDays` / エージェントの
  パターンは設定ファイルを手で編集しないと変えられない。ツールバーは既に混んで
  いるので、作るなら設定ダイアログにまとめる
- **エージェントの追加** — 上の手順で採取してから。Gemini CLI は一度入れたが、
  実機で日本語が入力できず（PaneDeck からは UTF-8 で正しく届いていることは確認済み）
  外した（#10）
- **ユーザー定義の待機パターン** — #10 で「作らない」と判断した。ユーザー由来の
  正規表現を 300ms ごと × ペイン数で回すため、壊滅的バックトラッキングで
  メインプロセスが固まる。やるなら**正規表現ではなく単純な文字列一致から**
